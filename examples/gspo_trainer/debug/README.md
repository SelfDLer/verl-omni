# NPU full-parameter training/rollout consistency debug

This run retains real pretrained weights and the Qwen3-Omni architecture, but
uses only the first four Thinker text layers. It trains **all retained Thinker
parameters**, including the vision/audio encoders, with `lora_rank=0`. It uses
full-weight synchronization, not LoRA merging. Rollout graphs stay enabled.

## Config and checkpoint

[`qwen3_omni_4layer.json`](qwen3_omni_4layer.json) is a config overlay:

```json
{
  "enable_audio_output": false,
  "thinker_config": {"text_config": {"num_hidden_layers": 4}}
}
```

The preparer merges it into the source checkpoint's complete config. It is
not an incomplete replacement that could introduce Transformers defaults.
Only text depth and the inference-only Talker/codec switch change. Hidden
sizes, heads, MoE experts/router, vocabulary, RoPE, all vision/audio layers,
projections, tokenizer and processor files remain unchanged. Four text layers
retain the three usual DeepStack injections and a subsequent decoder layer.
The preparer rejects depths that lose configured injections or dense/MoE
layer types.

Inputs follow video2's separate video and soundtrack segments. This does not
exercise the alternative `use_audio_in_video=true` interleaved-token path.

The actor supports `hf_config_path`, but rollout and processor setup read
`model.path`. Therefore a separate actor-only config is insufficient.
`prepare_debug_model.py` exports a common directory with the complete merged
config and retained tensors, which actor, tokenizer, processor and rollout
all load. Removed-layer weights are filtered so correctness does not depend
on differing loaders' treatment of unexpected weights.

Preparation processes local safetensors shard by shard, preserves tensor
values/dtypes, rebuilds the index and records a manifest. It never instantiates
the full model or allocates NPU memory. It needs disk space for the reduced
checkpoint and CPU memory for retained tensors from one source shard.
Subsequent launches reuse a matching completed export. Source files are never
modified; stale output causes an error. Use a new output directory after
changing source or config.

## Run

Use the dependencies, parquet and sourced CANN/ATB environment from the
[video2 recipe](../qwen3_omni/README_nextqa_video2.md). Download the source
checkpoint locally first.

```bash
export MODEL_PATH=/models/Qwen3-Omni-30B-A3B-Instruct
bash examples/gspo_trainer/debug/run_nextqa_video2_npu.sh
```

The first launch prepares `${MODEL_PATH}-debug4`; later launches reuse it.
To prepare separately:

```bash
python examples/gspo_trainer/debug/prepare_debug_model.py \
  --source /models/Qwen3-Omni-30B-A3B-Instruct \
  --config examples/gspo_trainer/debug/qwen3_omni_4layer.json \
  --output /models/Qwen3-Omni-debug4
```

Override `DEBUG_CONFIG` and `DEBUG_MODEL_PATH` to select another depth/cache.
Mount the exported directory at the same absolute path on all Ray workers.

Defaults: 4 NPUs, TP=2, eight questions per batch, first 32 candidate training
rows, at most four validation rows, 128 response tokens, two responses per
question, two training steps and final validation. Initial validation,
automatic resume and checkpoints are disabled. Video/audio inputs and the
8,192-token prompt budget are preserved. Increase `data.train_max_samples`
if prompt filtering leaves fewer than one batch.

Graph capture sizes are `[1,2]` with two concurrent requests per replica; the
full recipe uses `[1,2,4,8]`. Actor `use_torch_compile=false` is a separate
training setting. Initial export, model loading and graph capture still take
time; local CPU tests do not measure NPU speedup.

## Consistency evidence

The synchronous trainer independently recomputes actor logprobs for the exact
response tokens generated by rollout. Bypass and importance/rejection
corrections are disabled. Temperature=1, top-p=1, top-k=-1, repetition
penalty=1 and raw rollout logprobs keep the compared distributions unmodified.

`outputs/nextqa_consistency/step_000001.{json,pt}` records the comparison after
initial synchronization; step 2 follows the first training update and its
full-weight synchronization. JSON contains valid/nonfinite token counts,
masked logprob MAE, maximum absolute error, p95 and signed mean. PT contains
paired actor/rollout logprobs, response IDs and masks for inspecting outliers.
These are sampled-token diagnostics, not full-vocabulary KL. Empty/nonfinite
batches have `consistency/valid=0`; no arbitrary tolerance is called a pass.

Check finite, nonzero actor gradient norms and learning rate too. A reduced
model may never answer correctly; identical group rewards yield zero GRPO
advantage. Such a run checks initial parity and reload execution, but cannot
prove synchronization of changed parameters. Increase samples/responses or
depth; do not treat a zero-gradient run as post-update validation. The final
update is not followed by another training logprob comparison in a two-step
run; use three steps to inspect two updates.

Compare graph and eager runs in separate output directories:

```bash
DEBUG_OUTPUT_DIR=outputs/parity_graph bash examples/gspo_trainer/debug/run_nextqa_video2_npu.sh
DEBUG_OUTPUT_DIR=outputs/parity_eager bash examples/gspo_trainer/debug/run_nextqa_video2_npu.sh \
  actor_rollout_ref.rollout.enforce_eager=true
```

For a same-weight/no-learning control add `actor_rollout_ref.actor.optim.lr=0`.
Each comparison pairs the same response tokens within its run. Generations
across graph/eager runs are not guaranteed identical.

For a full-depth control, copy the JSON overlay and set the original text
depth, select it via `DEBUG_CONFIG`, use a distinct `DEBUG_MODEL_PATH` and
increase NPU resources if necessary. This preserves the same full-parameter
path and diagnostics. A reduced model can reproduce media/position, numerical
kernel and synchronization defects, but cannot certify full-depth parity,
long-context behavior, memory pressure or accuracy.

`--cfg job` inspects launch parameters without exporting/loading weights.
Final Hydra overrides are forwarded. Overriding LoRA, bypass, sampling or model
paths changes the experiment; keep all three model paths consistent.

CPU checks (including a small real Transformers save/export/load round trip):

```bash
python -m pytest -q tests/utils/test_qwen3_omni_debug_model_on_cpu.py \
  tests/trainer/omni/test_consistency_debug_on_cpu.py
```
